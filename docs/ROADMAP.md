## 一、基本功能：没有就不算可用

这一层管“看清楚”：打开仓库，马上能看懂发生了什么。

| 功能 | 要求 | 状态 | 现状和缺口 |
|---|---|---|---|

| | 颜色稳定：同一条分支始终同一个颜色 | ✅ | 颜色按分支名分配（`BranchColors`），图、标签、侧边栏圆点同色；悬停或选中提交时只亮那条线 |
| | 每行显示短 hash、提交信息、作者、相对时间 | ✅ | 相对时间每分钟刷新，悬停看完整时间；时间取作者时间 |

## 二、重要功能：拉开差距、让人愿意天天用

这一层管“能理解”和“能顺手操作”。可视化工具最大的价值在于让人**操作前就看懂后果**。

| 功能 | 要求 | 状态 | 现状和缺口 |
|---|---|---|---|
| 常用写操作 | 暂存、取消暂存 | ✅ | 文件列表每行右边一个勾选框，未暂存和已暂存各有一条底栏：左边 ⋯ 菜单（暂存所选、丢弃所选…、忽略所选加入 .gitignore 或 .git/info/exclude、取消暂存所选；忽略只作用于所选里的新文件，已跟踪的跳过），右边已选个数和全选；批量命令用 `--pathspec-from-file` 从标准输入传路径，不受命令行长度限制，批量丢弃前确认并写明其中几个新文件会被删除。列表可在平铺和按文件夹间切换（只有一个子目录的中间层合并成一行，文件夹勾选带上其下所有文件，可全部展开／收起），可左右滑动（勾选框不动），左栏可拖宽（260dp 到 560dp，且不超过页面一半），视图和宽度记在设置里；hunk／单行，统一与并排 Diff 共用选择；选中行生成补丁后交给 `git apply --cached`；二进制、大文件等只能整文件暂存，仍显示只读 diff |
| | 提交、切换、新建、删除分支 | ✅ | 新建分支从本地分支右键「从这里新建分支…」（起点是该分支最新提交）或提交右键进入，工具栏不设按钮；默认勾选「创建后切换过去」（`git switch -c`），工作区改动不冲突就带过去，冲突时 Git 拒绝且不建分支。还有修改上次提交、重命名分支、打标签、克隆；远程分支双击或右键检出为跟踪它的本地分支 |
| | merge、rebase、cherry-pick、revert、reset | ✅ | 普通 rebase 保留合并拓扑，支持重启继续／跳过／保留空提交／中止；reset 支持三种模式；确认后直接执行 |
| | 储藏：保存、查看、apply、pop、drop | ✅ | 储藏页可看每个文件的 diff |
| | fetch、pull、push | ✅ | 独立 fetch；pull 支持 merge／rebase／ff-only，有上游时一步完成（获取所选远程分支后直接集成），无上游时先选择；「拉取设置…」修改策略和上游，按仓库保存，支持自定义 refspec；分支右键可直接推送任意本地分支（不切换当前分支；有上游推到上游，没有就推到 origin 并设为上游；推别的分支失败时不给针对当前分支的「先拉取」「重试」按钮）；推送被拒绝时可强制推送（`--force-with-lease`，需确认）；获取、拉取、推送进行中可取消 |
| 操作反馈 | 进行中、成功、需处理和失败有明确提示 | ✅ | 共用右下角浮层卡片（2026-11-16 由顶部整行条改成浮层）；成功 5 秒后收起，悬停或展开详情时保留，警告和失败手动关闭；完整输出可展开、选中和复制，提供重试、先拉取或放弃；本地改动、分支、储藏、冲突保存、克隆和文件忽略操作接入统一异常处理，执行期间阻止重复写入；暂存、取消暂存、丢弃成功时不出提示，超过 400 毫秒才显示进度 |
| 操作确认 | merge、rebase、cherry-pick、reset 前说明后果 | ✅ | 小确认框列出后果摘要：带入／重放／离开分支的提交数、是否快进、预计冲突文件（`git merge-tree`，Git 2.38+）、硬重置会丢弃改动的文件数。只读计算，不演练、不复制工作区；不在图上预览，变基不预判冲突 |
| | 拖拽分支完成 rebase 或 merge | ✅ | 侧边栏／图标签拖拽到分支，选择方向后确认；先切换分支再合并／变基，冲突中止（含重启后）返回原分支并保留额外本地改动 |
| 冲突解决 | 三方对比，逐块选择保留哪一边 | ✅ | index stage 1/2/3 来源、可展开 base、块选择与全文编辑；文件切换保留草稿，保存核对外部修改，二进制／删除支持整文件选择 |
| Blame 和文件历史 | 看每行是谁在哪次提交改的，并能一路追溯 | ✅ | 保留来源路径与行号，支持重命名追溯、父版本区间、合并父选择、删除前版本和前后导航；新增行到引入处终止 |
| 两个引用对比 | `main...feature` 各自领先的提交和文件差异 | ✅ | 分支（本地或远程）右键「与当前分支比较」进入比较页；双向独有提交计数与独立分页，点提交跳回历史；固定 OID，分支移动后自动重新解析；从共同祖先／直接比较两端的文件差异，多共同祖先选择、无祖先提示、交换方向；分支被删时显示原因 |
| 分支过滤 | 只列出一条或几条分支历史上的提交，和 `git log <branch>` 一样 | ✅ | 从侧边栏右键分支「只看此分支／加入分支过滤」添加，过滤生效时历史上方才出现过滤条；本地／远程分支多选并集，与文件过滤组合；分页和搜索共用引用快照，失效引用明确提示 |
| Diff 语法高亮 | 按文件类型给代码着色 | ✅ | Kotlin／Java／JS／TS／JSON／Python；提交、本地、stash、引用对比共用，旧新源码独立后台分词；1 MiB／20,000 行回退，32 MiB 缓存 |
| Reflog 视图 | 找回丢失的提交 | 🟡 | 日常入口暂时隐藏，保留实现，待打磨后开放。HEAD 或指定引用分页查看，按 OID 打开不可达提交，从操作前／后创建恢复分支；对象被清理时提示 |
| 多仓库 | 最近仓库、快速切换 | ✅ | |
| 文件浏览 | 按目录看工作区的所有文件，包括被忽略的 | ✅ | 侧边栏“文件”：一棵带列的树（2026-11-16 由左右两栏合并），文件夹原地展开，列状态、大小、修改时间；点表头按名称、大小或修改时间排序，再点一次反向，目录总在前面，排序方式会记住。目录从磁盘读，展开时才读，git status 只标状态、补上还没提交的删除；被忽略的标灰，可以隐藏；文件夹里有改动只在名字后加小黄点。顶部按名称筛选：后台扫描所有未被忽略的目录（上限 20 万项，超出提示不完整），只留匹配项和它们的上级并自动展开，匹配的字高亮；被忽略的目录不进。键盘上下／左右／回车。不预览内容，双击文件交给系统打开；右键在 Finder 中显示、复制路径、查看改动、查看历史、把未跟踪的文件或文件夹加入 .gitignore。已经提交的删除不显示，看历史 |
| 键盘操作 | j/k 移动、快捷键执行命令 | ✅ | 图与分支列表焦点导航；命令面板（⌘⇧P）与 Cmd/Ctrl 快捷键，工具栏不再单设「命令」按钮；拉取、推送按钮右键可进入「拉取设置…」「强制推送…」；输入框保留文本撤销，Esc 退出搜索／选择不终止 Git |

## 优先级

第一层已全部完成（2026-11-05），第二层功能已实现（2026-11-06）。

1. 继续维护并发写入回归；写操作不做整仓备份，保持与命令行相当的耗时。
2. 合并、变基、cherry-pick、重置、拉取确认后直接执行，是否安全交给 Git 判断；确认框的摘要只用只读命令，不创建临时仓库。
3. 保持大历史分页和后台 Diff 分词。
4. 后续改进和未完成的真实窗口／外部服务验证见 [待办与验证缺口](PLAN.md)。已删除功能不再作为待交付节点。
